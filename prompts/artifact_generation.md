# Artifact final candidate — ChatGPT featuring Claude

당신은 공식 방송통신심의 사례를 방송 전 사전검토용 제작물로 재구성하는 데이터 편집자다.

목표는 법률 판단을 다시 쓰는 것이 아니라, 공식 의결 기록으로부터 실제 제작자가 방송 전에 사내 심의 담당자에게 제출할 수 있었던 콘텐츠 사실을 복원하는 것이다.

입력된 `raw_text`에는 실제 방송 내용뿐 아니라 위원회 판단, 관련 규정, 의결 결과와 사후 정보가 섞여 있을 수 있다. `사안에 대하여`, `논의 결과` 같은 특정 marker나 문단 위치에 의존하지 말고 각 문장의 의미를 기준으로 선별하라.

## 정보 선별 원칙

1. 다음과 같은 직접적인 콘텐츠 사실은 최대한 보존한다.

- 실제 발언과 자막
- 광고 문구와 내레이션
- 화면, 장면과 영상 연출
- 출연자·진행자·쇼호스트의 행동
- 상품 설명과 시연
- 숫자, 가격, 비율과 조사 결과
- 방송 시각과 편성 정보
- 채널과 프로그램 정보
- 생방송 또는 녹화 여부

2. 위원회의 판단 문장 안에 들어 있더라도 객관적인 제작 사실이 입력에 명시되어 있으면 보존할 수 있다.

예를 들어 입력에 특정 안내 자막을 표시하지 않았다고 직접 적혀 있다면, 현재 제작안에 해당 안내가 포함되어 있지 않다고 재작성할 수 있다.

3. 다음과 같은 사후 판단과 절차 정보는 제거한다.

- 위반 여부와 법률적 평가
- 부적절성, 오인 가능성, 권리 침해 등에 관한 심의 결론
- 규정명과 조항 번호
- 문제없음·의견제시·권고·주의·경고·과징금
- 위원회 판단과 논의
- 민원
- 방송 후 해명·사과·수정·삭제
- 추가 제출 자료
- 제재 및 감경 사유

4. 부재나 누락은 입력에 명시된 경우에만 쓴다.

법적 기준을 보고 `고지하지 않는다`, `표시가 없다`, `필수 정보가 누락되었다`는 사실을 새로 추론하지 않는다.

## 재작성 원칙

- 아직 방송하지 않은 제작자가 자신의 제작안을 설명하는 1인칭 평서체로 작성한다.
- 첫 문장은 가능한 경우 `[방송일] 방송 예정인 ○○를 준비 중이다`와 같이 제작자의 관점이 드러나도록 시작한다.
- 한국어에서는 주어를 생략할 수 있으므로 모든 문장에 `나는`을 반복할 필요는 없다.
- 질문은 공통 question이 별도로 담당하므로 artifact에는 넣지 않는다.
- 인사말, 제목과 서명도 넣지 않는다.
- 원문에 직접 인용된 발언·자막·광고 문구는 가능한 한 표현과 순서를 그대로 보존한다.
- 숫자, 가격, 비율, 제품명과 고유명사를 임의로 바꾸지 않는다.
- 주변 설명은 압축할 수 있지만 쟁점이 되는 표현을 순화하거나 법률 용어로 치환하지 않는다.
- 원문에 없는 인물, 대화, 장면, 제작 의도, 효과나 배경을 만들지 않는다.
- `domain`은 문체 선택에만 사용하며 새로운 사실을 추론하는 근거로 사용하지 않는다.
- `broadcast_date`는 예정 방송일로 자연스럽게 포함한다. 원문 안의 조사일·사건일·행사일을 방송일로 바꾸지 않는다.
- 원문 메타데이터가 내부적으로 모순되거나 파싱 오류가 명백한 경우에는 임의로 고쳐 쓰지 말고 해당 정보만 생략한다.
- 정보가 부족하면 그럴듯하게 채우지 말고 확인되는 사실만 간결하게 쓴다.

## 도메인별 관점

- `broadcast_program`: 프로그램 제작진이 뉴스 원고, 대본, 자막, 출연자 발언과 장면 구성을 설명한다.
- `broadcast_ad`: 광고 제작자가 광고 카피, 화면 문구, 영상 연출과 송출 조건을 설명한다.
- `product_sales`: 판매방송 제작진이 쇼호스트 대본, 상품 시연, 가격·효능 자막과 판매 조건을 설명한다.

## 변환 예시 1 — 상품판매방송

입력:

```text
domain: product_sales
broadcast_date: 2026-05-08
raw_text: 쇼호스트가 관절 건강 제품을 소개하면서 “3일만 드시면 무릎 통증이 사라집니다”라고 말하고, 의사 가운을 입은 출연자가 제품을 시연하였다. 해당 표현이 질병 치료 효과가 있는 것처럼 오인하게 할 우려가 있다고 판단하여 ‘경고’를 의결하였다.
```

출력:

```json
{"artifact":"5월 8일 방송 예정인 관절 건강 제품 판매방송을 준비 중이다. 쇼호스트가 “3일만 드시면 무릎 통증이 사라집니다”라고 소개하고, 의사 가운을 입은 출연자가 제품을 시연하는 장면을 넣을 예정이다."}
```

## 변환 예시 2 — 방송광고

입력:

```text
domain: broadcast_ad
broadcast_date: 2026-06-12
raw_text: 대출상품 광고에서 “직업과 신용등급에 관계없이 누구나 즉시 승인”이라는 자막과 내레이션을 사용하였다. 실제로는 별도의 심사 조건이 적용됨에도 이를 알리는 자막이나 멘트를 포함하지 않아 소비자를 오인하게 할 수 있다는 이유로 ‘주의’를 의결하였다.
```

출력:

```json
{"artifact":"6월 12일 방송 예정인 대출상품 광고를 제작 중이다. “직업과 신용등급에 관계없이 누구나 즉시 승인”이라는 자막과 내레이션을 사용하며, 별도의 심사 조건을 알리는 자막이나 멘트는 현재 광고안에 포함되어 있지 않다."}
```

## 변환 예시 3 — 방송프로그램

입력:

```text
domain: broadcast_program
broadcast_date: 2026-07-03
raw_text: 뉴스 프로그램에서 형사사건을 보도하면서 피의자의 실명을 자막으로 표시하고 얼굴이 식별되는 영상을 모자이크 없이 방송하였다. 위원회는 피의자의 인격권을 침해할 우려가 있다고 판단하여 ‘권고’를 의결하였다.
```

출력:

```json
{"artifact":"7월 3일 방송 예정인 뉴스 프로그램을 준비 중이다. 원고에서 피의자의 실명을 언급하고 화면 자막에도 실명을 표시하며, 얼굴을 식별할 수 있는 영상은 별도의 모자이크 처리 없이 사용할 예정이다."}
```

## 이번 입력

```text
domain: {DOMAIN}
broadcast_date: {BROADCAST_DATE}
raw_text: {RAW_TEXT}
```

출력은 다음 JSON object만 사용한다. 다른 설명은 출력하지 않는다.

```json
{"artifact":"제작자가 1인칭으로 설명하는 방송 전 콘텐츠 상황"}
```
